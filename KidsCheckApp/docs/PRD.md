## 1. 产品概述

### 1.1 产品定位

KidsCheck 是一款面向家庭的 Android 学习打卡应用，帮助父母远程设定孩子的每日学习任务，由爷爷奶奶在现场监督完成并拍照记录，形成闭环的学习管理流程。

### 1.2 目标用户

| 角色 | 画像 | 核心诉求 |
|------|------|---------|
| 父母 | 上班族，无法全天陪伴孩子 | 远程设定任务、查看完成情况、验证作业质量 |
| 爷爷奶奶 | 基本手机操作能力，日常看护孩子 | 简单明了地知道今天要做什么、一键完成打卡 |
| 孩子 | 8岁（大宝）、5岁（小宝） | 通过积分获得成就感和奖励动力 |

### 1.3 核心价值

- **降低沟通成本**：父母不用每天打电话告知任务，爷爷奶奶打开app即可看到
- **留痕可追溯**：作业完成有照片存证，父母可异步审核
- **激励机制**：积分兑换让孩子主动完成任务

## 2. 功能需求

### 2.1 角色与权限

| 功能 | 父母 | 爷爷奶奶 |
|------|:----:|:--------:|
| 查看今日任务列表 | ✓ | ✓ |
| 打卡（确认完成+拍照） | ✓ | ✓ |
| 查看打卡进度 | ✓ | ✓（仅当天） |
| 查看/审核打卡照片 | ✓ | ✗ |
| 管理任务模板 | ✓ | ✗ |
| 语音输入任务 | ✓ | ✗ |
| 管理积分奖励库 | ✓ | ✗ |
| 家庭管理（邀请成员） | ✓ | ✗ |
| 积分兑换操作 | ✓ | ✓ |

- 孩子无独立账号，作为"档案"挂在家庭下
- 爷爷奶奶由父母通过邀请码加入家庭

### 2.2 任务模板管理

#### 2.2.1 周模板

- 父母为每个孩子按"周一至周日"设置重复任务
- 每个任务包含：名称、类型（书面/阅读）、描述（可选）、积分值
- 支持排序调整优先级

#### 2.2.2 条件任务

- 触发条件：当日全部必做任务标记完成
- 每个孩子可配置多个条件任务
- 条件任务完成后同样获得积分

#### 2.2.3 语音输入

- 使用 Android 系统语音识别（STT）将语音转文字
- 调用大模型做文本意图解析（输入为短文本，成本极低）
- 支持的语音指令示例：
  - "每周一给大宝添加数学口算"
  - "把周三的英语阅读删掉"
  - "增加一个条件任务，画画30分钟，5积分"
- 解析后展示确认卡片，用户确认后才执行

### 2.3 每日任务生成

- 每天 00:00 定时任务自动运行
- 根据当天星期几，为每个孩子从模板生成 daily_task（status=pending）
- 条件任务不预先生成，待必做任务全部完成后动态插入

### 2.4 打卡流程

#### 2.4.1 书面类任务

```
查看今日任务列表 → 点击任务 → 点"完成打卡" → 必须拍照存证 → 确认上传 → 完成
```

- 拍照为必选步骤
- 照片作为作业完成的证据
- 父母稍后可在进度页查看照片进行审核

#### 2.4.2 阅读类任务

```
查看今日任务列表 → 点击任务 → 点"确认完成" → 完成
```

- 拍照为可选（可拍可不拍）
- 由爷爷奶奶现场确认孩子确实完成了阅读

#### 2.4.3 通用规则

- 打卡时自动记录：操作人、完成时间
- 完成后积分自动发放
- 当所有必做任务完成，条件任务自动出现在列表中

### 2.5 打卡进度

独立页面，包含：

- **孩子切换** Tab
- **日期选择器**（父母可查看历史，爷爷奶奶只看当天）
- **进度条**：已完成数/总任务数
- **时间线**：按完成时间排列，已完成项显示时间戳，附照片图标可点击查看
- **积分汇总**：今日获得 / 累计积分

#### 照片审核（父母专属）

- 点击时间线中的照片图标可全屏查看
- 可标注"有效"或"需重做"（标注仅做记录，不影响积分）

### 2.6 积分系统

#### 2.6.1 积分获取

- 完成任务后自动发放，金额由模板配置
- 每个孩子独立积分账户

#### 2.6.2 奖励库

- 由父母创建和管理
- 每个奖励包含：名称、所需积分、描述、图片（可选）
- 奖励为家庭级，所有孩子共享奖励库

#### 2.6.3 积分兑换

- 孩子在爷爷奶奶或父母协助下选择奖励
- 兑换后扣除积分，生成兑换记录（status=pending）
- 父母确认兑现后状态变为 fulfilled

### 2.7 家庭管理

- 父母注册时创建家庭
- 添加孩子档案（姓名、年龄、头像）
- 生成邀请码，爷爷奶奶扫码/输入码加入
- 一个家庭支持多个父母和爷爷奶奶角色

## 4. 技术架构

### 4.1 技术选型

| 层 | 技术 | 说明 |
|---|------|------|
| Android 客户端 | Kotlin + Jetpack Compose | 现代声明式 UI，原生性能 |
| 后端 API | Python FastAPI | 轻量高效，AI 生态友好 |
| 数据库 | PostgreSQL | 关系型，适合结构化任务数据 |
| 文件存储 | 本地文件系统 / OSS | 存储打卡照片 |
| 语音识别 | Android 系统 STT | 免费，离线可用 |
| 意图解析 | 大模型 API（通义千问/GPT） | 解析语音文本为结构化指令 |
| 定时任务 | APScheduler / Celery Beat | 每日任务生成 |

### 4.3 数据模型

#### 核心表

| 表 | 关键字段 | 说明 |
|---|---------|------|
| `family` | id, name, invite_code | 家庭 |
| `user` | id, family_id, role, name, phone | 用户（父母/爷爷奶奶） |
| `child` | id, family_id, name, age, avatar | 孩子档案 |
| `task_template` | id, child_id, weekday, title, type, description, points, sort_order | 周任务模板 |
| `conditional_task` | id, child_id, trigger_condition(v1固定为"all_required_done"), title, type, description, points | 条件任务模板 |
| `daily_task` | id, child_id, date, source_template_id, title, type, status, completed_at, completed_by | 每日任务实例 |
| `check_in_photo` | id, daily_task_id, photo_url, uploaded_by, uploaded_at, reviewed, review_note | 打卡照片 |
| `point_account` | id, child_id, balance | 积分账户 |
| `point_transaction` | id, child_id, amount, reason, related_task_id, created_at | 积分流水 |
| `reward` | id, family_id, title, cost_points, description, image_url | 奖励 |
| `reward_redemption` | id, child_id, reward_id, points_spent, redeemed_at, status | 兑换记录 |

#### 关键索引

- `daily_task`: (child_id, date) 联合索引 — 查询某天某孩子的任务
- `point_transaction`: (child_id, created_at) — 积分流水查询
- `task_template`: (child_id, weekday) — 模板调度查询

| 模块 | 端点 | 方法 | 说明 |
|------|------|------|------|

## 5. 非功能需求

### 5.1 性能

- 任务列表加载 < 1秒
- 照片上传支持压缩（上传前客户端压缩至 1MB 以内）
- 离线时缓存今日任务列表，联网后同步

### 5.2 安全

- 用户认证使用 JWT Token
- 照片存储不公开访问，需携带 Token 请求
- 家庭数据隔离，用户只能访问自己家庭的数据

### 5.3 可靠性

- 打卡操作需要本地暂存，网络恢复后补传
- 每日任务生成失败需要有重试机制
